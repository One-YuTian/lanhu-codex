# 切图下载与重命名

默认只保存最终图片文件。未经用户明确要求，不创建任何本地文件夹，不下载或保存设计 JSON、接口原文、清单、对照表、日志等附带文件。获取工具返回的 JSON 元数据可以在内存中解析，不等于将 JSON 下载到本地。

1. 从标记正文取得 pid/tid/imageid；只有链接时先用 `lanhu_parse_url`。调用 `lanhu_get_design_slices({project_id,team_id,image_id})` 获取 slice_id、name、bounds、url、logical_size、scale_urls，按 next_offset 分页。用户只选部分对象时，用 slice_id 与标记 id 匹配；组内资产可用 `lanhu_get_elements` 的 parent_id 确认归属，不能默认下载整页。
2. 根据原图层名、页面上下文、实际图片和用户命名参考判断用途。必要时用 `lanhu_get_resource` 查看少量候选图片。确认是否可导出；没有对应切图时报告，不伪造下载 URL。
3. 优先沿用用户提供的命名参考和项目已有约定；否则采用下表常用短名。根据实际内容命名，不机械音译图层名，不把所有容器都命名为 popup。

| 元素内容或用途 | 优先名称 |
| --- | --- |
| 页面背景、弹窗、容器、面板 | `bg`、`popup`、`box`、`panel` |
| 标题、按钮、光效、引导手势 | `title`、`btn`、`light`、`hand` |
| 进度条及其背景 | `bar`、`bar_bg` |
| 提示及其背景、礼物 | `tip`、`tip_bg`、`gift` |
| 顶部、底部装饰 | `top`、`bot` |

同一目录有多个同类元素时使用 `popup1`、`popup2`、`btn1`、`btn2`，编号按页面阅读顺序（上到下、左到右，同位时按 slice_id）稳定分配。仅一个时用不带数字名称。允许保留 `bar_bg`、`tip_bg` 等常用下划线。检查已有文件和本次所有目标名，大小写不敏感地避免冲突；已有文件不得覆盖，跳过已确认相同的资产或顺延编号。多页素材也使用现有目标目录，通过文件名消除冲突；只有用户要求按页面分目录时才创建子目录。

4. **默认导出 WebP**，使用 `.webp` 文件名；只有用户明确要求其他格式时才改用该格式。倍率按用户或项目要求选择；无要求时默认取 `scale_urls["1x"]`，没有时用 url。在 OSS 图片处理参数中保留缩放操作，并将格式转换为 `/format,webp`，保留其他签名参数。核对真实返回格式，不得只把 PNG/JPEG 改后缀伪装成 WebP；CDN 不支持转换时，应在内存中使用现有图像库转换，不将中间 PNG 或 JSON 落盘，无法转换则报告失败。保持透明度，不擅自降低分辨率或添加额外压缩参数。多倍率用文件名 `@2x` 等约定，不擅自创建平台目录。
5. 保存到用户明确指定且已存在的目录，或当前项目中已存在、用途明确的素材目录。不主动创建 `assets/lanhu/<image_id>/`、页面子目录或其他文件夹。如果没有可确定的现有目标目录，先询问保存位置；用户明确要求创建时才创建。通过 HTTPS GET 携带 `Referer: https://lanhuapp.com/web/`，不携带 Cookie。不跟随重定向到未知来源。批量下载在本机完成，不将所有图片转成 base64 写入对话。

可用附带脚本，在内存中构建数组清单，每项形如 `{"slice_id":"7423","name":"finger","url":"实际蓝湖HTTPS图片URL","filename":"hand.webp"}`，通过标准输入传入，**不要创建清单 JSON 文件**：

```sh
node <本技能目录>/scripts/download-slices.mjs - <现有素材目录>
```

脚本默认请求真实 WebP，不创建目录，不写 `lanhu-assets.json` 或任何 JSON 附件，只保存图片并在标准输出报告简短结果。只有用户要求创建目录时使用 `--create-directory`；只有用户要求保留其他格式时使用 `--original-format`。脚本校验域名、大小、真实图片格式及同名冲突；filename 由 Agent 按语义分配。失败后只重试失败项，不能为重试新建输出文件夹。URL 过期时重新取地址。

6. 核对下载数量、图片可解码性、实际尺寸和 WebP 格式；原 slice_id/name 与新文件名的对应关系仅保留在工作内存或必要的简短回复中，不生成对照 JSON。
7. 下载校验完成后，自动读取并调用 [Lanhu Compressed Picture](../lanhu-compressed-picture/SKILL.md)，按其 MCP 调用流程，通过任务列表和处理工具压缩本次成功下载的图片，不仅仅打开面板。仅传入这些文件的绝对路径，不传整个目标目录，不处理目录中原有文件或其他任务。用户明确要求不压缩时遵从该要求。依据返回状态核对结果；压缩失败时保留已下载图片并简述失败项，不无限重试。
8. 交付时简述保存位置和失败项，不贴大量签名 URL，也不介绍压缩实现。仅当用户要求项目引用同步时更新引用并验证页面可用。
